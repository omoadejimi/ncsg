## Explain what is known

A useful error message explains:

1. What happened, in plain language.
2. What this means for the person’s money, information or progress.
3. What they can do next, or whether they need to wait.

Use a calm, direct tone. Avoid blame, jokes and unexplained system codes. If the outcome is unknown, say so rather than presenting a failure or success as confirmed.

## Match the message to the transaction state

These are illustrative copy templates, not operational promises. Replace placeholders with verified product details. Confirm the state, retry behaviour, return process and support route with engineering and operations before using the copy.

| Confirmed state | Suggested message | Next action and conditions |
| --- | --- | --- |
| Completed | Your transfer of [amount] to [recipient] is complete. | View receipt. Use only when completion is confirmed. |
| Failed, no debit | We could not send [amount]. No money was taken. | Offer “Try again” only when another attempt cannot duplicate the payment. |
| Outcome unknown | We are checking this transfer. We do not yet know whether it completed. | Check status. Explain how to avoid a duplicate payment and when to get help. |
| Failed, money taken | The transfer failed. [Amount] was taken from your account. We will return it by [verified deadline]. | Track return or get help. Use only when the debit and return commitment are confirmed. |

Do not copy a return window from another service. Explain what happens if the confirmed deadline passes. Prefer “returned to your account” where “reversal” would need explanation.

## Show the correction

<DoDont>
<Do>
Check the BVN and try again.

A Bank Verification Number (BVN) has 11 digits.
</Do>
<Dont>
Invalid BVN.
</Dont>
</DoDont>

Where retrieval help is relevant, use `*565*0#` with the registered-phone requirement and fee explained in [Government IDs](/docs/nigeria/government-ids). A correctly formatted number can still fail an identity check; do not describe that as a length error.

## Distinguish connection problems

- **No connection:** explain whether the task has been sent or saved, if the system knows. Offer a safe recovery action.
- **Slow response:** explain that the result is still being checked. Avoid asking for another payment while its outcome is unknown.
- **Unavailable service:** name the affected service when known and provide a working status or support route.

Offer a USSD or other fallback only when the specific service supports it. Verify its action, eligibility and fee. Do not assume a bank-specific code works for everyone or safely repeats an uncertain transaction.

Explain automatic retries and preserve progress where the implementation supports it. Avoid repeated retries that use data without making progress clear.

## Accessibility considerations

- Use a polite status announcement, such as `role="status"`, for updates that can wait. Reserve `role="alert"` for urgent information needing immediate attention; it is assertive, not polite.
- For form errors, associate the message with its field, for example through `aria-describedby`. Provide text that identifies the error and explains a correction where possible.
- On failed form submission, use a tested, focused error summary with links to fields. Do not add competing live announcements without checking for duplicate speech.
- Maintain required contrast in each theme and state. Do not rely on colour, icons or capital letters alone.
- Test timing, focus and announcements with keyboard and screen-reader users in the actual flow.

See [W3C status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [the status role technique](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22.html), [the alert pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) and [GOV.UK’s error-summary pattern](https://design-system.service.gov.uk/components/error-summary/).

## Example beyond payments

<CopyExample label="Document upload — illustrative confirmed failure">
We could not upload your document.

Your application answers are saved, but the document has not been added. Check your connection and try uploading it again.
</CopyExample>

Use this only when saved answers and the failed upload are confirmed. If progress is not saved, say what needs to be entered again. Give accepted file types and the verified size limit beside the upload field.
