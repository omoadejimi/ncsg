## Choose a manageable starting point

Choose languages through audience research and available translation support. Yoruba, Hausa, Igbo and Nigerian Pidgin are examples, not a complete list of Nigerian languages. Do not infer a person’s preferred language from their name or location.

Start with one complete task in one additional language. Provide a clear language choice and explain when content is available only in another language.

## A translation workflow

1. **Prepare the source.** Make the meaning clear. Give each string an ID and record the task, screen, audience, tone, variables and character constraints. Include errors and recovery states.
2. **Agree terminology.** Choose a translator with relevant language and subject knowledge. Record the language variety, orthography and terms with an explanation of each decision.
3. **Translate for meaning.** Preserve warnings, consent choices and consequences. Treat Nigerian Pidgin with the same care as other languages. Machine output needs human review before publication.
4. **Review independently.** Ask another qualified speaker to check meaning, spelling, tone and task context. Resolve disagreements in a shared decision log.
5. **Test the interface.** Allow text to wrap and expand. Check small screens, enlarged text, Unicode, diacritics, fonts and line breaks. Mark page and passage languages correctly in the implementation and test available screen-reader pronunciation.
6. **Check comprehension.** Ask intended users to complete the task and explain key information in their own words. Record the sample, language variety and limits of the test.
7. **Maintain both versions.** Name an owner and backup, keep source and translation versions linked, and review translations when the source changes. Explain any fallback rather than silently switching languages.

Do not use a fixed expansion percentage as a guarantee that a translated layout will work. See [W3C guidance on text size in translation](https://www.w3.org/International/articles/article-text-size/) and [language declarations](https://www.w3.org/International/questions/qa-html-language-declarations).

## A reusable translation record

For each string, record:

- string ID and source version
- source text, screen and intended action
- language and variety
- proposed translation and terminology notes
- translator and independent reviewer
- comprehension and interface test results, including unresolved issues
- publication status and next review trigger.

This is a workflow template. NCSG does not present an unreviewed translation here as an approved language pattern.

## Evidence and limits

**Standards-informed workflow; pilot needed.** W3C resources support the implementation checks. No reviewed NCSG translation or language comprehension study is presented here. Validate the workflow through a limited pilot before expanding coverage. For contributions, use the [evidence record in Editorial standards](/docs/operations/editorial-standards).
